# Windows標準ショートカットとロックコマンド

## 目的と収録範囲

WindowsToolsの静的コマンドとして、Windowsの操作を名前で選び、ショートカット・ジェスチャー・トレイなどへ割り当てられるようにする。自由登録のキー送信一覧やホストの保存型カスタムコマンドは使わない。

対象は2026-10-19に確認した[Microsoftの一覧](https://support.microsoft.com/ja-jp/accessibility/windows/keyboard-shortcuts-in-windows)の「Windows キー キーボード ショートカット」と「複数のデスクトップのキーボード ショートカット」。タスクバーなど別の節へ範囲を広げない。

- Win+Ctrl+Shift+B（画面の復旧）、Win+L、Win+カンマ（押下中のプレビュー）は収録しない。
- 環境依存の操作も収録し、必要な機能・アプリ・機器・設定を説明へ記載する。設定の自動変更・アプリの自動導入・代替操作への自動切り替えは行わない。
- 2節で重複するWin+Tabと、条件によって説明が分かれるWin+Cはそれぞれ1コマンドにする。絵文字のピリオド／セミコロン、検索のQ／Sは送るキーを選べるよう別コマンドにする。
- PCロックは独立した「Windowsをロックする」コマンドにし、既存のLockWorkStation経路へ接続する。自動ロックの設定や無操作時間を変更しない。

## 定義と登録

静的な定義の正本は`windows-shortcuts.json`。ID・表示名・キー・説明を持ち、DLLへ埋め込んで読み込む。実行時に外部の定義ファイルや設定へ依存しない。`scripts/update-shortcut-manifest.ps1`で同じ定義をmanifestへ反映し、`-Check`で一致を検証する。

コマンドIDは`at365.windows-tools.windows.<固定ID>`、専用ロックは`at365.windows-tools.lock-windows`。0.2.0の既存12コマンドと設定を保つ。0.2.0で廃止された`send.<ID>`、キー送信一覧、Shortcut/SendAsyncは復活させず、残った旧設定と割り当ても移行・変換・削除しない。固定コマンドは合計79件となる。静的コマンドも従来のReplaceAsyncへ毎回含め、設定変更後も残す。manifestにも宣言し、停止中の割り当て候補と説明を保持する。初期キー割り当てと外部実行の公開は追加しない。

本体の宣言・開始・動的置換と.NET Runtimeの共通上限は256件で、今回の登録79件はその範囲に収まる。名前空間・重複・タイトル・説明の検証と、拒否時の元の登録への復元は維持する。

## 表示と説明

短い動作名をタイトルにし、送信キーと必要条件を説明に載せる。既存のカスタムコマンドの説明検証（任意、1,000 UTF-16コード単位、LF正規化）を共用する。静的コマンドのmanifest／実行時登録にも任意のdescriptionを追加し、共通のコマンド一覧、ショートカット・ジェスチャーの一覧、コマンドパレットで表示する。カスタムコマンドも同じ共通表示へ説明を渡す。

既存の左右移動・全高などは挙動を維持する。追加するWindowsのスナップ操作は、それらとは別の名前・IDを持つ。仮想デスクトップの終了はアプリの終了と区別して説明する。

## キー送信と互換性

静的コマンドから`context.AppDock.CallAsync`で本体の`input.sendKeys`を呼び、既存のsendInput許可・取消・押下解放待機・対象変更拒否・再入防止を使う。送信完了と実際の効果は区別し、自動再送しない。最前面を対象とするので、別のアプリを動かす場合はグローバルショートカットなどから呼ぶ。

共通の送信文法へWin単独、Pause、PrintScreen、Period、Semicolon、Slash、Plus、Minusを追加する。記号はSDKでは意味を保持し、入力workerで送信対象のスレッドのGetKeyboardLayoutとVkKeyScanExWにより仮想キーと必要な修飾キーへ解決する。配列を変更・キャッシュしない。未対応の記号変換は失敗として返す。日本語／英語配列のセミコロン・プラスの違いを固定のOEMキーで代用しない。1回の送信で必ずキーを解放し、押しっぱなしは作らない。

本体0.62.3、WindowsTools0.2.1を対象とし、Appletの最低本体版を0.62.3へ更新する。設定・保存ファイル・既存の呼び出し契約の増減や破壊的変更がないため、WindowsToolsは0.2.0からパッチ更新。本体0.62.3の実装・発行物は維持する。0.2.0のジェスチャー対象プロセス名/PIDの判定修正も維持する。

## 検証方針

- 静的一覧の重複・除外・manifest一致、旧キー設定の無視と非移行、設定更新・停止・取消、専用ロックの単発実行を模擬APIで確認する。
- 共通の説明文と件数上限、送信文法、JIS／US記号解決、既存送信と権限・取消の回帰を確認する。
- 最終発行物の固定EXEとDLLを隔離配置し、説明の表示・検索、静的一覧、旧キー設定UIとsend登録の非復活、再起動・停止を確認する。
- 実ロック、HDR変更、録画・撮影、入力方式変更、仮想デスクトップの作成・終了などを全件自動実行しない。模擬送信と実Windowsで確認した効果をVERIFICATIONで区別する。

ローカル発行までを対象とし、commit・push・GitHub Release・実利用先へのdeployは別工程とする。
