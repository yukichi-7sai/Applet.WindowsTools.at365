# Applet.WindowsTools.at365 機能・操作・設定

ウィンドウの移動・高さ調整・最小化・最大化・復元・終了、Windows標準ショートカット、最前面アプリのフォルダー表示、消灯予約、Windowsのロック、無操作時の自動ロックを提供する AppDock 用 DLL Applet です。

## 動作環境

**Windows x64 / AppDock 0.85.9以降**が必要です。Windows標準のキー操作には「設定 → 操作の許可」の「Windowsへのキー・操作メッセージ送信」をONにしてください。既存のウィンドウ操作・消灯・ロックには、この入力許可は不要です。

## 導入・更新

1. AppDockをトレイの「終了」から完全終了します。
2. 配布物の `extension.json`、`Applet.WindowsTools.at365.dll`、`Applet.WindowsTools.at365.deps.json` を、AppDock.at365.exeの隣の `extensions/Applet.WindowsTools.at365/` に配置します。更新時も配布物一式をそろえて置き換えてください。
3. AppDockを起動し、「Applet」一覧で有効にします。操作やキーの割り当てはAppDockから行います。

利用するPCにはAppDockの動作環境が必要です。詳細は[AppDockの導入案内](../../AppDock.at365/docs/usage.md)を参照してください。

## コマンドと設定

| コマンドID（`at365.windows-tools.` に続く部分） | 動作 |
| --- | --- |
| `open-folder` | 最前面アプリの実行ファイルがあるフォルダーをエクスプローラーで開く |
| `display-off` | 設定した秒数後にディスプレイを消灯。再実行すると予約し直す |
| `cancel-display-off` | 保留中の消灯予約を取り消す |
| `toggle-auto-lock` | 自動ロックの有効／無効を切り替えて保存 |
| `left` | 中央より右なら中央へ、次に左端へ、さらに左のモニターの右端へ移動 |
| `right` | 中央より左なら中央へ、次に右端へ、さらに右のモニターの左端へ移動 |
| `full-height` | 横位置と幅を基本的に保ち、タスクバーを除く作業領域の高さに合わせる |
| `center` | サイズを保ち、見えているウィンドウ枠を現在の作業領域の縦横中央へ移動 |
| `minimize` | ウィンドウへ通常の最小化要求を送信 |
| `maximize` | ウィンドウへ通常の最大化要求を送信 |
| `restore` | 最大化したウィンドウを通常のサイズに復元 |
| `toggle-maximize` | 最大化中なら元のサイズに復元し、それ以外なら最大化を要求 |
| `close` | 通常の終了要求を送信。保存確認・終了のキャンセルは対象アプリが処理 |

| 分類 | 設定 | 既定値 | 範囲・意味 |
| --- | --- | --- | --- |
| コマンドの動作 | ディスプレイ消灯コマンドの待機時間（秒） | 5秒 | 1〜3600秒 |
| セキュリティ | 無操作時の自動ロック | 無効 | マウス・キーボードの両方を監視 |
| セキュリティ | 自動ロックまでの無操作時間（分） | 360分 | 1〜1440分 |

予約と無操作判定は1秒間隔で確認するため、実行は指定時刻から約1秒遅れることがあります。消灯時間の設定変更は次の予約から反映されます。自動ロックは有効化／監視時間の変更から数え直し、起動前の無操作だけを理由に直ちにロックしません。同じ無操作期間には1回だけロックを要求し、新しい入力があると再び監視します。

Appletの無効化・再起動・ホスト終了で消灯予約と監視を停止します。消灯予約は次の起動へ持ち越しません。PCロックはサインアウトやスリープではありません。

### Watch との対応

- Watch の「最前面アプリのフォルダーを開く」はプロセスの実行ファイルの場所を開く機能です。WindowsToolsも同じ動作です。エクスプローラーで閲覧しているフォルダーや、エディターで編集中の文書のフォルダー、プロセス内部の作業ディレクトリを取得する機能ではありません。
- Watch の消灯用ショートカットは1秒待機でした。WindowsToolsでは秒数を設定できます。
- Watch の自動ロックはマウスのみ・6時間固定でした。「PCの操作がなかった場合」に合わせて、WindowsToolsは マウスとキーボードの無操作時間を使い、分単位で変更できます。

### Windows標準コマンドを使う

Windowsキーと仮想デスクトップの66件、メディア・音量キー7件、「Windowsをロックする」、ターミナル・電源関連5件を固定コマンドとして提供します。ウィンドウ操作など13件と合わせて92件を利用できます。[コマンド一覧と利用条件](windows-shortcuts.md)を参照してください。共通のコマンド一覧とパレットに、送信キー・必要なアプリ・機器・Windowsの条件が表示され、説明の内容でも検索できます。

全92件をMCPにも公開しています。AIからコマンドのID・説明を取得し、ショートカット等へ割り当てたり、許可に応じて直接実行したりできます。シャットダウン・再起動・サインアウトは確認ダイアログや待ち時間を設けずに要求します。ロック・消灯・ウィンドウの終了や、撮影・録画・マイクの切り替えも、それぞれの説明と現在の対象を確認して実行してください。キー送信・プロセス起動にはMCPとApplet双方の該当する操作許可が必要です。

「Windowsをロックする」は直ちにWindowsへロックを要求し、自動ロックの設定は変更しません。対応しない機能の自動導入や設定変更は行いません。

### ターミナル・電源・メディア・音量

「Windowsターミナルを起動する」「Windowsをシャットダウンする」「Windowsを再起動する」「Windowsからサインアウトする」「Windowsのシャットダウン画面を開く」を提供します。これら5件は、本体の共通プロセス起動APIを使用するため、「設定 → 操作の許可」のApplet列で情報取得・コマンド実行・プロセス起動を許可してください。

ターミナルはWindows PowerShellのStart-Processでwt.exeを起動します。実行エイリアスを通常のEXEとして事前にファイル検査しません。Windowsターミナルとアプリ実行エイリアスが必要です。シャットダウンと再起動はshutdown.exeの/sまたは/rと/t 0、サインアウトは/lを指定します。待ち時間・独自確認・強制終了の/fは追加しません。実行前に作業を保存してください。権限・組織ポリシー・未保存アプリにより終了操作が拒否・中止される場合があります。

「Windowsのシャットダウン画面を開く」はWindows PowerShellからShell.ApplicationのShutdownWindowsメソッドを呼び、標準の選択ダイアログを開きます。画面で操作を選びOKを押すまで終了操作は行いません。キャンセルできます。Alt+F4の送信や最前面アプリの終了は行いません。プロセス起動の完了は起動受付を表し、実際の終了・ダイアログ表示を保証しません。失敗時の自動再送は行いません。

メディアは再生／一時停止・停止・次のトラック・前のトラックの4件、音量はミュート／解除の切り替え・上げる・下げるの3件です。既存の「Windowsへのキー・操作メッセージ送信」許可を使います。メディアキーはWindowsと対応アプリに処理を委ね、特定の再生アプリを選びません。音量操作はWindowsの音声出力が対象で、マイクやAppDockだけの音声設定ではありません。入力フックや既定のキー割り当ては追加しません。

### 独自のキー送信

本体の「設定 → カスタムコマンド」で「キーを送信する」を登録し、ショートカット等を割り当てます。[本体のカスタムコマンド](../../AppDock.at365/docs/custom-commands-design.md)を参照してください。

### ウィンドウ操作の対象と制約

移動はWindowMoverの作業領域基準、負のモニター座標、DWMの不可視枠補正、上下端付近の吸着（上60px／下70px）を引き継ぎます。隣のモニターは現在の作業領域の幅だけ中心点をずらして選び、作業領域の上端または下端が一致する場合に移動します。端のモニターでは折り返しません。

移動・高さ調整ではマウスカーソル、フォーカス、Z順を変更しません。デスクトップ、タスクバー、タイトルなし、非表示、最小化中のウィンドウは除外します。中央移動は最大化中には何もせず、作業領域より大きいウィンドウも縮小しません。復元はWindowsの通常操作で、移動・高さ調整の取り消しや最小化した別ウィンドウの呼び戻しではありません。固定サイズ・全画面アプリや権限差により操作が適用されない場合があります。コマンド完了は要求の送信完了を表し、対象アプリによる処理完了を保証しません。

「開始までの秒数」で遅延起動でき、「更新を確認」でGitHubの正式リリースを手動で確認できます。

## AppDockからの更新

「設定 → バージョン情報・更新」の一括更新、またはこのAppletの個別更新ボタンを利用できます。配布元が`update.json`と`update.zip`を提供している場合に対応します。更新元は「インストール済みのApplet」の「更新元の設定」で変更し、保存してください。ローカルフォルダー・UNC・HTTP(S)・GitHub Releaseに対応し、「既定に戻す」も利用できます。

更新内容を確認して再起動すると配布ファイル一式を交換します。AppDock側の設定・有効状態・保存データは保持します。詳細は[AppDockの更新操作](../../AppDock.at365/docs/usage.md#アップデート)を参照してください。

開発・ビルドについては[開発ガイド](../DEVELOPMENT.md)を参照してください。

## Codexからの設定変更

「ディスプレイ消灯コマンドの待機時間（秒）」（1〜3600秒）を取得・変更できます。変更は次に消灯を予約するときの待ち時間へ反映され、設定変更だけで消灯しません。実行済みの予約時刻は変わりません。自動ロックの設定値は設定取得・更新APIに含めません。消灯・ロックの実行と自動ロックの切り替えは、他の固定コマンドとともに公開しています。

## 共通の設定画面

AppDockの「設定」でWindowsToolsを選ぶと、「コマンドの動作」「セキュリティ」のカードから編集できます。本体と同じテーマ・入力欄・自動保存を使い、起動待ちは末尾の共通カードにあります。

説明文内の `[command:コマンドID]` は関連するコマンドを示します。リンク表示に未対応の本体では、タグが文字列として表示されます。
